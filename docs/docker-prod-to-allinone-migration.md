# Разовый перенос данных: Docker-прод → заводская машина

**Название файла историческое** — оно осталось от прежней поставки (ADR 0002,
заменено ADR 0004). Сейчас на машине стоят два отдельных приложения: сервер
`EkranchikServer.exe` и экран киоска `Ekranchik.exe`. На процедуру это не
влияет: каталог данных и логов общий и лежит на прежнем месте, а экран, будь
он встроенным в сервер или отдельным приложением, к данным не обращается
вообще.


Разовая процедура переноса накопленных данных с текущего Docker-прода
на заводскую машину с поставленным сервером `EkranchikServer.exe` без
Docker (ADR 0004: `docs/adr/0004-kiosk-and-server-as-two-apps.md`, issue #7).

После переноса машины живут независимо — **дальнейшей синхронизации нет**.
Повторный перенос (если понадобится) = повторить эту же процедуру,
он перезапишет данные на заводской машине. От настроек приложения
(`launcher/source_code/EkranchikServer`) процедура не зависит.

### Перенос с прежней поставки

Машина, на которой стояла прежняя поставка `EkranchikAllInOne.exe`
(ADR 0002, теперь заменено), обновляется на новую поставку без переноса
данных вообще: `%LOCALAPPDATA%\Ekranchik\data` и `%LOCALAPPDATA%\Ekranchik\logs`
те же самые, конфиг экрана (`kiosk_config.json`) и конфиг сервера
(`server_config.json`) лежат рядом и установщик их не трогает.

Переход выполняется обычным запуском того же установщика поверх прежней
поставки, с выбором нужного типа установки. Установщик сам:

1. Удаляет файлы прежней поставки (`EkranchikAllInOne.exe` и его
   sidecar-файлы).
2. Удаляет прежние ярлыки «Ekranchik» и «Ekranchik Полный пакет» и создаёт
   два новых: «Ekranchik (киоск)» и «Ekranchik (сервер)».
3. Раскладывает выбранные компоненты по каталогу, не трогая данные, настройки
   и логи.

Отдельно про автозапуск: устаревшее значение `EkranchikAllInOne` в
`HKCU\...\Run` удаляет сам сервер при первом старте (иначе Windows попыталась
бы поднять несуществующий файл); значение экрана `Ekranchik` не трогается.

Процедура ниже нужна, когда данные приходят не с этой машины, а с
Docker-прода (или с любой другой машины).

## 1. Что переносим, а что — нет

| Артефакт | Переносим | Почему |
|---|---|---|
| `ekranchik.db` (SQLite) | Да | Все учётные данные |
| `images/` (фото профилей + `*-thumb.jpg`) | Да | Без них дашборд без картинок |
| `active_excel*.json`, `app_settings.json` | Нет | Содержат пути исходной машины (контейнерные `/app/excel/...`, dev-пути); на заводской машине Excel и настройки задаются в окне настроек сервера |
| `profiles.db` | Нет | Legacy-файл, бэкендом не используется |
| `backend/.env` | Нет | Dev-конфиг, в пакет не входит (см. `scripts/build-full-package.ps1`) |

## 2. Где взять файлы на сервере (сверено с compose/env)

`infra/compose/docker-compose.prod.yml` монтирует хост-каталог в контейнер
и перекрывает dev-значения `backend/.env` своим `environment`:

```yaml
environment:
  - DATABASE_URL=sqlite+aiosqlite:////app/static/ekranchik.db  # стр. 18
  - STATIC_DIR=/app/static                                      # стр. 19
  - IMAGES_DIR=/app/static/images                               # стр. 20
volumes:
  - ../../static:/app/static                                    # стр. 28
```

Значения `backend/.env` (`DATABASE_URL=sqlite+aiosqlite:///../static/ekranchik.db`,
`IMAGES_DIR=../static/images`) в проде **не действуют** — их перекрывает
`environment` compose-файла (env-файл подключается через `env_file`, но
`environment` имеет приоритет). Итог: данные лежат в хост-каталоге репозитория
на сервере (пути относительно корня checkout'а):

- БД: `<repo>/static/ekranchik.db` (в контейнере `/app/static/ekranchik.db`)
- Фото: `<repo>/static/images/` (в контейнере `/app/static/images`)

## 3. Куда положить на заводской машине

`backend/app/core/config.py` (`default_data_dir` + `_apply_plant_defaults`):
без явных `DATABASE_URL`/`IMAGES_DIR` данные уходят в каталог данных
поставленного приложения —
`%LOCALAPPDATA%\Ekranchik\data` (порту `8083` пакет `scripts/build-full-package.ps1`
`.env` не содержит, так что действуют именно дефолты). Каталоги создаются сами
при старте (`ensure_data_dirs`), миграции — `alembic upgrade head` из lifespan.
Раскладка после переноса:

- `%LOCALAPPDATA%\Ekranchik\data\ekranchik.db`
- `%LOCALAPPDATA%\Ekranchik\data\images\`

## 4. Порядок действий

На **сервере** (каталог checkout'а репозитория):

1. Остановить прод-бэкенд, чтобы SQLite-копия была консистентной
   (копировать БД под записью нельзя):
   `docker compose -f infra/compose/docker-compose.prod.yml stop backend`
2. Скопировать `<repo>/static/ekranchik.db` и `<repo>/static/images/`
   на заводскую машину (любым способом: USB, сеть).
   Удобно скриптом из п. 5 — он же делает проверки.
3. Поднять прод обратно:
   `docker compose -f infra/compose/docker-compose.prod.yml up -d backend`

На **заводской машине**:

4. Убедиться, что сервер остановлен (не класть БД поверх
   запущенного процесса — скрипт без `-Force` откажется это делать).
5. Разложить файлы:
   `powershell -ExecutionPolicy Bypass -File scripts/copy-prod-data.ps1
     -SourceDb <путь>\ekranchik.db -SourceImages <путь>\images`
   (без параметров скрипт берёт `static/ekranchik.db` и `static/images`
   рядом с репозиторием и кладёт в `%LOCALAPPDATA%\Ekranchik\data`).
6. Запустить сервер (ярлык «Ekranchik (сервер)»). Миграции применятся
   автоматически при старте.

## 5. Скрипт

`scripts/copy-prod-data.ps1` — рядом со `scripts/build-full-package.ps1`.
Проверяет: источник БД и `images/` существуют, целевой каталог создаётся,
цель не занята запущенным процессом (найден `EkranchikAllInOne` — процесс
прежней поставки — либо висит python-бэкенд `-m uvicorn`, либо файл
целевой БД заблокирован — без `-Force` отказ с требованием остановить
бэкенд). Поддерживает `-WhatIf` для сухого прогона. `backend/.env`
скрипт никогда не копирует.

## 6. Проверка после переноса

1. Дашборд открывается: `http://localhost:8083`, данные (подвесы, смены,
   остатки) совпадают с продом на момент остановки из п. 1.
2. Картинки видны: фото профилей на дашборде грузятся (признак, что легли
   `%LOCALAPPDATA%\Ekranchik\data\images\`, а не только БД).
3. Перезапуск сервера не теряет данные (лежат вне пакета, переживают
   переустановку).

## 7. Экран киоска после переноса

Экран — отдельное приложение (`Ekranchik.exe`) и к данным не обращается: он
открывает дашборд по адресу из своих настроек. Поэтому:

1. Убедиться, что в настройках сервера виден «Адрес для экранов» и галка
   «Доступ из локальной сети» включена (иначе экран на отдельной машине
   дашборд не откроет).
2. В настройках экрана киоска указать этот адрес и нужный монитор.
3. Открыть дашборд с экрана: `http://<адрес-из-настроек-сервера>`. Данные
   на нём — те, что перенесли в п. 5.
