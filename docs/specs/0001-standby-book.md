# Спека 0001 — Запасная книга учёта

Статус: принята. Решение — [ADR 0009](../adr/0009-standby-book-follows-growing-rows.md).
Тикеты: 0008 (роли и API), 0009 (правило и фоновая задача), 0010 (экран),
0011 (документация), 0012 (приёмка).

## Проблема

Книгу учёта могут открыть на другом компьютере и заблокировать сохранение с
машины оператора. Автосохранение продолжает писать обе книги раз в 8 минут
или по кнопке, поэтому у основной книги mtime идёт, а строки не прибавляются.
Дашборд продолжает читать основную и показывает данные, которых уже нет:
оператор работает в запасной книге.

Время сохранения и размер файла **не различают** эти состояния: сохранение
переписывает файл целиком, и размер меняется, даже когда новых строк нет.
Различает только наполненность — число непустых строк с датой или номером
подвеса, то есть те же строки, что видит дашборд.

## Что должно получиться

- В диалоге «Ввести путь» задаются две книги: основная и запасная (запасная
  необязательна).
- Система сама читает ту книгу, в которой идут строки. Ручного выбора «читай
  сейчас эту» больше нет: «Применить» сохраняет роли.
- На строке статуса видно, какая книга читается: «основная» или «ЗАПАСНАЯ».
- Если читается запасная — на дашборде баннер: основная не пополняется с
  такого-то времени (или «нет данных о росте»).
- В журнале подвесов у каждой новой записи есть `book_name` и `book_path` —
  из какой книги взят вердикт.
- Автобэкап снимает **активную** книгу: работаем с запасной — копия ложится в
  тот же корень (`EXCEL_BACKUP_ROOT`, иначе каталог книги), но в папку с именем
  запасной книги (`<имя запасной>_backup`). Отдельной настройки и второго
  расписания нет.

## Автобэкап при переключении

Автобэкап (ADR 0007) читает `excel_service.current_path`, поэтому следует за
переключением сам:

- читаем основную → копии идут в `<основная>_backup`;
- читаем запасную → копии идут в `<запасная>_backup` в том же корне;
- при возврате на основную копии снова идут в `<основная>_backup`.

Папки двух книг не смешиваются: имя книги — часть имени папки. Ротация
(ступенчатая политика 0007) считается внутри папки, поэтому копии одной книги
не вытесняют копии другой.

## Правило

Опрос обеих книг раз в 30 секунд по `stat` и числу строк. Книга «растёт»,
когда строк с реальными данными стало больше, чем в прошлом замере.

| Состояние                                                     | Действие                         |
| ------------------------------------------------------------- | -------------------------------- |
| основная растёт                                               | читаем основную                  |
| основная не растёт 30 мин, запасная росла и обошла по строкам | читаем запасную                  |
| читаем запасную, в основной снова выросло строк               | читаем основную (сразу)          |
| основная пропала (файла нет)                                  | читаем запасную (сразу)          |
| основная есть, но не читается (сохраняется)                   | остаёмся, ждём                   |
| запасная пропала                                              | читаем основную                  |
| обе не растут                                                 | остаёмся, обычное предупреждение |
| запасная не задана                                            | только основная, режим выключен  |

Дополнительные условия:

- переключение на запасную требует, чтобы в ней было больше строк, чем в
  основной;
- обе книги растут — приоритет основной (в том числе при чтении запасной:
  рост основной возвращает на неё);
- время роста считается монотонным, календарные переводы часов на правило не
  влияют;
- после перезапуска сервера 30 минут наблюдения начинаются заново.

## Домен

- **Основная книга учёта** — книга, которую читают по умолчанию; первичный
  источник строк.
- **Запасная книга учёта** — вторая книга с теми же колонками, в которую
  оператор переходит, когда основная заблокирована. Не путать с **«Резервной
  копией книги учёта»** — снимком файла в `<книга>_backup`.
- **Рост строк** — прибавление строк с реальными данными (дата или номер
  подвеса), а не изменение mtime/размера.

## Контракты

### API

`POST /api/dashboard/excel/books`

```json
{
  "main_path": "\\\\host\\share\\Учет КПЗ 2026.xlsm",
  "reserve_path": "\\\\host\\share\\Учет КПЗ 2026 запасная.xlsm"
}
```

Ответ: `{ "success": true, "main": "...", "reserve": "..." | null, "active": "..." }`.
Ошибки: 400 — пустая основная, совпадение путей, не то расширение; 404 —
книга не найдена (с подсказкой про неподключённую шару).

`POST /api/dashboard/excel/select` (прежний вход) — делает указанную книгу
основной и читает её сейчас. Совпавшая с ней запасная сбрасывается.

`GET /api/dashboard/status/file` — дополнительные поля: `role`
(`main`/`reserve`/`null`), `main_file_path`, `reserve_file_path`,
`main_last_growth`.

`GET /api/dashboard/settings` — дополнительно `excel_reserve_path`,
`excel_role`.

### Хранение

Файл выбора `static/active_excel*.json` (имя из `EXCEL_ACTIVE_FILE_NAME`)
получает ключи `active_file`, `main_file`, `reserve_file`. Старый формат без
ролей читается: основная = `active_file`, запасная пуста.

### Владелец решения

Активную книгу по-прежнему выбирает `excel_service.current_path` (ADR 0003).
Фоновая задача `standby_book` переключает её через `set_active_file`, поэтому
статус, журнал, автобэкап и watcher видят один файл.

## Вне рамок

- Запись в книги и в папку `<книга>_backup` сверх существующего автобэкапа.
- Слияние содержимого книг: читается одна книга целиком.
- Настройка порогов через `.env`: 30 минут и 30 секунд — константы модуля.
- Новые экраны: только существующие строка статуса, диалог пути и настройки.

## Критерии приёмки

1. Норма: обе книги сохраняются вместе, дашборд читает основную, переключений
   нет.
2. Основная перестала пополняться 30 минут, запасная растёт — дашборд
   переходит на запасную; в статусе «ЗАПАСНАЯ», на экране баннер.
3. В основной снова выросло строк — возврат на основную без ручных действий.
4. Основная исчезла — переход на запасную в пределах одного опроса.
5. Запасная не задана или исчезла — читается основная, ошибка в статусе.
6. Журнал: новые записи содержат название и путь книги.
7. `mise run check` зелёный; backend-тесты правила покрывают все строки
   таблицы; dev-стенд жив после перезапуска.
8. При чтении запасной книги автобэкап кладёт копию в `<запасная>_backup` в
   том же корне, что и копии основной; папки книг не смешиваются.
