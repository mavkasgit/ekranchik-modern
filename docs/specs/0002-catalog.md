# Спека 0002 — Каталог артикулов

Статус: принята. Решение — [ADR 0010](../adr/0010-catalog-is-read-only-showcase.md).
Тикеты: 0015 (API и данные), 0016 (экран), 0017 (поиск и фильтры),
0018 (просмотр фото), 0019 (выпил), 0020 (документация и приёмка).
Внешняя задача: T-377 в ktm2000 (контракт синка и просмотрщик).

## Проблема

У полей каталога было два владельца. Данные артикулов приходят из каталога
KTM: синк обновляет `length`, `quantity_per_hanger` и фото, а киоск в это же
время умел создавать артикулы, править любые поля, удалять их, загружать и
кропить фото. Оператор менял норму — синк её откатывал; загруженное в киоске
фото жило до первого изменения исходника; удалённый артикул возвращался
следующим запуском. ZIP-экспорт остался промежуточным звеном: каталог
забирают синком, а не архивом.

Вёрстка фото-диалога не гарантировала «вписано в экран»: в невысоком окне
портретное фото вылезало за диалог и обрезалось, на узком — правая панель
съедала всю ширину (фото 8×12 px). Это лечилось подбором размеров вручную, а
не правилом.

Термины разъехались: в интерфейсе «профиль», в каталоге-источнике «артикул»,
в книге учёта снова «профиль». Паритет с KTM тянул в киоск ERP-функции
(алиасы, роли, импорт), которые здесь никто не просил.

## Что должно получиться

- Каталог — **витрина**: показывает артикул, наименование, длину, количество
  на подвесе и фото. Локально хранится и редактируется только **примечание**.
- Создание, удаление, правка полей, загрузка и удаление фото, кроп превью и
  ZIP отсутствуют. Артикул появляется и исчезает вместе с каталогом-источником;
  это администраторская процедура вне киоска.
- Поиск, сортировка и фильтры работают на клиенте по полному списку. Список
  приходит одним запросом, пагинации нет.
- Фото открывается **вписанным в экран**; доступны зум, панорамирование,
  копирование и скачивание; Esc закрывает.
- В интерфейсе — «Артикул», «Наименование», «Примечания». Ни источника, ни
  даты обновления, ни слова «синхронизация» в UI нет: для оператора это
  готовая система с понятными данными.
- Свежесть каталога — ответственность администратора; киоск её не показывает
  и не лечит.

## Домен

- **Артикул** — единица каталога, код (SKU), по которому оператор ищет
  изделие. В интерфейсе пишем «Артикул»; в коде и книге учёта — «профиль».
- **Наименование** — человекочитаемое описание артикула, приходит из
  каталога-источника. Не путать с примечанием.
- **Примечание** — единственные локальные данные киоска: не синхронизируется,
  не перезаписывается, живёт только на этом экране.
- **Длина** и **количество на подвесе** — параметры подвеса из
  каталога-источника; в киоске только читаются.
- **Превью** и **полное фото** — изображения артикула; в киоске только
  читаются.
- **Витрина** — режим каталога: данные приходят извне, киоск их показывает.
- **Синхронизация** — администраторская процедура пополнения витрины; в UI не
  упоминается.

## Контракты

### Данные

| Поле                    | Владелец         | В киоске                     |
| ----------------------- | ---------------- | ---------------------------- |
| `name` (артикул)        | каталог-источник | read-only                    |
| `description`           | каталог-источник | read-only, может быть пустым |
| `length`                | каталог-источник | read-only                    |
| `quantity_per_hanger`   | каталог-источник | read-only                    |
| `photo_thumb/full`      | каталог-источник | read-only                    |
| `notes`                 | киоск            | единственное редактируемое   |
| `usage_count`           | никто            | в API и UI не отдаётся       |
| `created_at/updated_at` | служебные        | read-only                    |

`usage_count` не инкрементируется ни одним сценарием, поэтому из ответа
каталога убирается; колонка в БД остаётся до отдельной миграции. `similarity`
и `match_priority` в UI не используются.

### API

`GET /api/catalog/all?limit=…` — полный список для витрины. Поля ответа:
`id`, `name`, `description`, `quantity_per_hanger`, `length`, `notes`,
`photo_thumb`, `photo_full`, `photo_thumb_version`, `photo_full_version`,
`created_at`, `updated_at`. Наличие фото интерфейс выводит из `photo_thumb` /
`photo_full`, отдельного `has_photo` в ответе нет.

`GET /api/catalog/{name}` — карточка артикула.

`GET /api/catalog?q=…` — поиск с приоритетами; остаётся как API, интерфейс
витрины его не вызывает.

`PATCH /api/catalog/{id}/notes` — единственная запись.

```json
{ "notes": "Аналог-ЮП-3168" }
```

Ответ — `ProfileResponse`. Пустая строка или `null` очищают примечание.
Ошибки: 404 — артикула нет, 422 — длиннее 2000 символов.

Удаляются: `POST /api/catalog`, `PUT /api/catalog/{id}`,
`DELETE /api/catalog/{id}`, `POST /api/catalog/{name}/photo`,
`PUT /api/catalog/{name}/thumbnail`,
`DELETE /api/catalog/{name}/photo[/full|/thumbnail]`,
`GET /api/catalog/export/zip`. Вместе с ними уходит генерация превью и
кроп на сервере: превью приходит из каталога-источника.

### Хранение

Миграция `002` добавляет `profiles.description` (`String(500)`, nullable).
Примечание остаётся `Text` с ограничением 2000 символов на схеме. Файлы фото
лежат в `IMAGES_DIR` как раньше; версия в URL — `mtime_ns-size` (не меняется).

### Синхронизация

Внешний контракт (исполняет скрипт в ktm2000, T-377):

- переносит артикул, наименование, длину, количество на подвесе и фото;
- длина у существующего артикула сопоставляется с любой длиной источника
  (±1 мм), иначе ставится основная;
- количество на подвесе берётся по режиму подвеса (ручной → ручное, авто →
  авто);
- новые артикулы создаются, пропавшие удаляются только явной командой
  администратора; отсутствие артикула в источнике не повод удалять его молча;
- фото обновляются по размеру файла: если файла нет на месте или его размер
  отличается от исходника KTM, картинка перезаписывается;
- `notes` не трогает;
- понятия «неактивный артикул» в витрине нет: все артикулы считаются
  активными, фильтра по активности нет;
- запуск только вручную; расписания и отметки о запуске в UI нет.

### Экран каталога

- Заголовок «Каталог артикулов», счётчик «N артикулов».
- Плитка: превью, «Артикул», наименование, бейджи «N шт/подв» и «N мм»,
  примечание в две строки. Кнопок правки и удаления нет; плавающей кнопки
  «+» нет.
- Таблица: фото, артикул, наименование, количество, длина, примечания,
  «Изменён». Сортировка — кликом по иконке в заголовке: до трёх столбцов,
  бейдж показывает приоритет; повторные клики меняют направление и снимают
  ключ.
- Фильтры — в заголовках колонок: клик по подписи открывает поповер с
  поиском и списком значений. У артикула, наименования и примечания поиск
  фильтрует строки «содержит», у длины и «с фото» выбираются точные значения,
  количество и «изменён» фильтруются диапазоном «от/до». Панели диапазонов
  над списком нет. Активные фильтры общие для плитки и таблицы: счётчик и
  чипы со снятием в тулбаре, сброс — кнопкой в правом верхнем углу таблицы.
  В плитке заголовков нет, поэтому там тот же набор фильтров открывается
  кнопкой «Фильтры» в тулбаре (одна и та же реализация поповера).
- Поиск клиентский, 200 мс, по артикулу, наименованию и примечанию.
- Режим (плитка/таблица), сортировка и фильтры запоминаются в `localStorage`.
- Состояния: скелетон, «Ничего не найдено» с учётом поиска и фильтров,
  «Каталог пуст» без подсказок об источнике, ошибка с «Повторить».
- Карточка артикула: поля показаны текстом, а не заблокированными полями.
  Примечание — textarea с автосохранением по потере фокуса и тостами
  «Сохранено» / «Не удалось сохранить». Кнопки «Сохранить» нет.
- Картинки: `loading="lazy"`, `decoding="async"`, `alt` — артикул.
- Ширина < 768 px: диалог на весь экран, фото сверху, примечание снизу.

### Просмотр фото

- Открывается по клику на превью или на фото в карточке.
- Стартовый масштаб — «вписано»; «1×» означает вписано, а не натуральный
  размер. Зум 1–4×, колесо и пинч, панорамирование мышью и пальцем, двойной
  клик — сброс, кнопки «+»/«−» на случай, если жесты недоступны.
- Esc закрывает; кнопка закрытия — в углу; полноэкранный режим браузера
  сохраняется.
- Копирование в буфер (с фолбэком через `execCommand` для HTTP в локальной
  сети) и скачивание файла.
- Кропа, замены и удаления фото нет.

## Вне рамок

- Авторизация, роли и права: сеть — периметр, write-эндпоинтов, кроме
  примечания, нет.
- Пагинация и виртуализация: грузим всё, потолок — 1000 артикулов.
- Кроп, отдельное превью, загрузка и удаление фото.
- Создание, удаление и правка полей артикула.
- ZIP-импорт и ZIP-экспорт, Excel, алиасы, массовые операции, drag&drop между
  артикулами, теги и «недавние», тёмная тема каталога, аудит, офлайн-режим,
  мультиязычность.
- Полный паритет с ktm2000: ERP-поля (код, цвет, состав, маршруты, флаги) в
  витрину не переезжают.
- Колонка «Профиль» на дашборде остаётся: она повторяет книгу учёта. «Артикул»
  — термин каталога, а не замена языка книги.

## Критерии приёмки

1. В каталоге нет кнопок и пунктов меню «Создать», «Изменить», «Удалить»,
   «Загрузить фото», «Кроп», «Экспорт ZIP»; нет плавающей кнопки «+».
2. Карточка показывает артикул, наименование, длину, количество и фото; эти
   поля не редактируются. Примечание сохраняется по потере фокуса, тост
   подтверждает, после перезагрузки значение на месте.
3. Поиск, сортировка и фильтры работают без обращения к серверу; фильтры
   общие для плитки и таблицы, счётчик и сброс работают; переключение режима
   их сохраняет.
4. Фото открывается целиком при 1920×1080, 1366×768, 1024×600, 900×500 и
   390×844: прямоугольник картинки внутри экрана и внутри диалога, пропорции
   сохранены, прокрутки нет. Зум 1–4×, панорамирование, Esc, копирование и
   скачивание работают; на тач-экране — пинч.
5. `GET /api/catalog/all` и `GET /api/catalog/{name}` не содержат
   `usage_count`; удалённые write-эндпоинты отвечают 404/405;
   `PATCH /notes` отвечает 200/404/422.
6. `PATCH /notes` не меняет `length`, `quantity_per_hanger`, `description` и
   фото; повторный синк не затирает примечание.
7. UI не содержит слов «KTM», «синхронизация», «источник», «обновлено из»,
   даты синка и подсказок о происхождении данных.
8. `mise run check` и `mise run test` зелёные; e2e каталога проходит.
9. Синк (T-377): новый артикул появляется с наименованием, длина и количество
   совпадают с источником, фото обновляются, когда файла нет или размер
   отличается от исходника, примечания не тронуты.

## Тесты

- Backend: отсутствие write-маршрутов, `PATCH /notes` (200/404/422), описание
  в ответе, миграция `002`, неизменность примечания при синке.
- Frontend: vitest на чистые функции фильтров, сортировки, выбора значений
  длины и математику зума.
- E2E: один сценарий каталога — поиск, фильтр по длине, открытие фото
  (вписано), зум, Esc, сохранение примечания. Вьюпорты 1366×768 и 900×500.
