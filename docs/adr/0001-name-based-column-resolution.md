# Резолв колонок Excel по имени заголовка (с позиционным фолбэком)

## Context

Бэкенд читает лист «Подвесы» книги учёта Excel позиционно: `usecols=[3, 4, 5, 7, 8, 10, 11, 12, 16, 19]` с последующим переименованием. Книгу редактируют вручную на сетевом диске — вставка колонки (например, «Фамилия» сразу после «Смена») сдвигает все последующие колонки и молча ломает парсинг. Позиционная привязка уже дала сбой: реальный файл содержит «Фамилия», а `usecols` попадает на соседние колонки.

## Decision

Резолвить колонки по **имени заголовка** (строка заголовков — строка 3 листа, строки 1–2 служебные), зеркаля логику `kpz-uchet/vba/ColRef.bas`:

- нормализация заголовка: lowercase + срез крайних пробелов/табов/переносов (внутренние сохраняются);
- при дубликате заголовка («№ по порядку» в A и E) берётся **последнее** совпадение;
- необязательные поля (например, «Фамилия») не мапятся — их наличие не влияет на парсинг;
- если хотя бы одно из 10 полей нашлось по имени — используем найденные имена, ненайденные берутся из старых позиций (`usecols`);
- если не нашлось **ни одного** поля — чистый позиционный режим (старое поведение) с warning в лог.

Чтение двухпроходное: сначала строка заголовков (быстро), затем второй проход `usecols` по найденным позициям — сохраняет оптимизацию calamine.

Отдельно: параллельно с этой работой в рабочем дереве уже лежала несвязанная правка матчинга unload-событий (`dashboard.py`): она меняла выбор «максимальная entry_seconds» на «самый новый валидный по порядку файла». Эта правка внесла двойной разворот (`reversed(candidates)` при том, что `get_products` уже отдаёт записи от новых к старым) — матчилась самая старая строка, и тест `test_closest_match_wins` падал. В ходе этой работы правка исправлена (убрано `reversed`, восстановлен guard «вход не позже выхода на 3ч», диагностика считает diff лениво) — см. коммит/рабочее дерево. Бага в самом HEAD не было: там тест проходил.

## Why

Вставка/перестановка колонок в книге — штатная операция, файл живёт на сетевом диске и редактируется людьми. Привязка по имени устойчива к этому. Потребители данных (dashboard, analysis, opcua, фронтенд) уже работают по именам полей — меняется только точка чтения в `excel_service.py`. VBA не может импортировать Python, поэтому «единая логика» = одинаковые правила, задокументированные в `column_map.py` и `ColRef.bas`, с перекрёстной ссылкой в обоих модулях.
