# Экран киоска и сервер — два отдельных приложения

**Статус:** принято (заменяет [ADR 0002](0002-full-mode-all-in-one-without-docker.md))

## Контекст

ADR 0002 решило заводскую задачу — «всё на одной машине без Docker» — одним
приложением `EkranchikAllInOne.exe`: в одном процессе трей, окно настроек,
бэкенд на embedded Python и окно экрана киоска. Решение сработало: встроенный
Python рядом с exe, доступ по локалке, порт 8083, данные в
`%LOCALAPPDATA%\Ekranchik\data` — всё это работает и остаётся нужным.

Разошлись два свойства приложения:

1. **Экран не поднимается надёжно.** Встроенное окно `KioskForm` живёт в
   процессе сервера: его сбой, пересоздание WebView2, переключение профиля
   DPI и падение при старте — всё это наблюдаемо пользователем как «сервер не
   работает», хотя бэкенд жив. При этом отдельно поставленный экран киоска
   работает ровно так же годами: тот же WebView2, тот же дашборд, тот же трей.
2. **Режим смешивает разные задачи.** Машина-сервер (ввод данных, OPC UA,
   Excel по сети) и машина-экран (только полноэкранный дашборд на
   выделенном мониторе) обслуживаются разными людьми. Одно приложение
   заставляет ставить Python и бэкенд на машину-экран, а на серверной машине
   — держать лишнее окно на втором мониторе. Автозапуск и обновления у обоих
   тоже общие: обновление экрана и обновление бэкенда приезжают одним куском.

Ограничения, которые решение обязано сохранить: embedded Python рядом с exe
(системный Python на целевой машине не нужен), самостоятельная раздача
`dist/` бэкендом, порт 8083 и доступ по локалке по умолчанию, файлы данных и
логов в `%LOCALAPPDATA%\Ekranchik` (переживают переустановку), один
установщик и тихая установка без вопросов.

## Решение

Экран киоска и сервер — **два отдельных приложения**, которые ставятся одним
установщиком:

**Сервер** — `EkranchikServer.exe` (фоновое приложение, .NET 9 WinForms).
Встроенный Python + uvicorn, раздача собранного веб-интерфейса, чтение книги
учёта Excel по сети, OPC UA, трей («Настройки», «Выход»), окно настроек,
автозапуск. Своего экрана у него нет: дашборд открывает отдельное приложение
экрана, а адрес для экранов оператор смотрит в настройках сервера. Конфиг —
`%LOCALAPPDATA%\Ekranchik\server_config.json`, логи —
`%LOCALAPPDATA%\Ekranchik\logs\server-*.log` и `backend-*.log`, значение
автозапуска в `HKCU\...\Run` — `EkranchikServer` (`--silent`).

**Экран киоска** — `Ekranchik.exe` (отдельный процесс, .NET 9 WinForms,
WebView2). Открывает заданный URL дашборда на выделенном мониторе, свой трей
(«Переключить монитор», «Режим простоя», «Настройки», «Выход»), окно настроек
с адресом дашборда, монитором и автозапуском, автозапуск Windows
(`--no-gui`). Конфиг — `%LOCALAPPDATA%\Ekranchik\kiosk_config.json`, значение
автозапуска — `Ekranchik`. Своего бэкенда у него нет и не было: это определение
киоска по глоссарию (CONTEXT.md).

**Дистрибуция** — один установщик с типами «Только киоск», «Сервер» и
«Оба на одной машине» (выборочная установка), два ярлыка в «Пуске»:
«Ekranchik (сервер)» и «Ekranchik (киоск)». Каналы обновлений не пересекаются:
экран обновляется сам (канал `v`, ассет `Ekranchik.exe`), сервер — через
установщик (канал `full-v`, ассет `EkranchikSetup.exe`). Снятие галочки при
повторной установке удаляет снятое приложение целиком — файлы и ярлыки (в
«Пуске» и на рабочем столе), — чтобы в меню не оставалось ссылки на
несуществующий exe; ярлык оставленного приложения не трогается, данные,
настройки и логи не затрагиваются.

**Рантайм браузерного движка.** Экрану нужен вечнозелёный Microsoft Edge
WebView2 Runtime, а на чистой корпоративной машине его может не быть.
Установщик ставит его сам: если по реестру (per-machine либо per-user) рантайма
нет, скачивается официальный вечнозелёный загрузчик и запускается с
`/silent /install` — молча, без перезагрузки и без требования прав
администратора (установщик работает с правами пользователя, поэтому рантайм
встаёт в тот же профиль). Нет сети — установка не падает: причина уходит
оператору внятным сообщением сразу после установки, а экран при
неудачном старте сам показывает окно с причиной. Ручных шагов оператора для
машины экрана не остаётся.

**Миграция с merged-поставки.** Файлы, ярлыки и устаревшее значение автозапуска
`EkranchikAllInOne` (в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`)
вычищает установщик — в том числе на машине, где поставили только экран и
сервер так и не запускали: иначе Windows при каждом входе пыталась бы запустить
несуществующий файл. Сервер удаляет это же значение при старте (страховка),
значение экрана `Ekranchik` не трогает ни то, ни другое. Данные лежат в общих
каталогах и переезжают на новую поставку без преобразований — процедура
переноса прежняя (`docs/docker-prod-to-allinone-migration.md`).

Общие типы (конфигурация экрана, автозапуск Windows) лежат в отдельном файле
`KioskShared.cs` и компилируются в оба приложения: экран пользуется ими сам,
сервер собирает то же окно настроек и тоже пишет своё значение в `Run`.
Общее окно настроек остаётся единым кодом, но показывает разные секции: у
сервера — книга учёта, OPC UA, тестовые данные, доступ по локалке и адрес для
экранов; у экрана — адрес дашборда, монитор, автозапуск.

## Известные ограничения

- **Рантайм WebView2 ставит установщик, но только вечнозелёный и только в
  профиль пользователя.** Прав администратора установщику не нужны, поэтому на
  машине без общесистемного Edge WebView2 рантайм встаёт per-user: под другим
  учётным записям его не видно (там нужен рантайм, установленный IT-машиной).
  Если сети при установке нет, рантайм не ставится — оператор узнаёт об этом из
  сообщения установщика и из окна самого экрана. Проверять это надо на
  машине-экране, а не на серверной.
- **Адрес дашборда задаётся в настройках экрана, а не сервера.** Сервер
  только показывает в своих настройках адрес для экранов
  (`http://<ip>:8083`); оператор переносит его в настройки экрана вручную.
  Снятая галка «Доступ из локальной сети» делает этот адрес недоступным с
  других машин — экран, стоящий на отдельном компьютере, перестаёт видеть
  дашборд.
- Пока работает и не выключен экран на второй монитор, у экрана есть
  «Автозапуск на втором мониторе (без окна настроек)»: при двух и более
  мониторах и включённой галке окно настроек при старте не показывается.
  Чистая установка кладёт этот признак выключенным (вместе с адресом
  `http://localhost:8083` — портом дашборда), поэтому окно настроек оператору
  показывается всегда; живой `kiosk_config.json` установщик не затирает.

## Considered Options

- **Оставить merged-приложение как есть** — отклонено: не устраняет главную
  причину (экран и сервер делят процесс), экран-приложение при этом уже есть и
  работает не хуже.
- **Сервер запускает экран отдельным процессом сам** (экран как дочерний
  процесс сервера) — отклонено: это предыдущая попытка из ADR 0002, вернувшая
  проблему «две одинаковые иконки в трее» и зависимость экрана от жизни
  сервера; теперь экран запускают как обычное приложение.
- **Общий установщик на оба приложения, но с одним ярлыком** — отклонено:
  пользователь не может запустить экран без сервера и наоборот, а тип установки
  всё равно выбирается при установке.
- **Перевести сервер в веб-интерфейс без десктопного приложения** — отклонено:
  теряется трей с корректной остановкой uvicorn, настройки Excel/OPC UA и
  автозапуск, ради которых на заводе и нужен .NET-тре launcher.
