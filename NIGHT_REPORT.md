- `parse_excel_time` по-прежнему возвращает `(0,0,0)` для пустой и битой ячейки — это существующий контракт. Отличает их `is_valid_excel_time`: в журнале и в сопоставлении заполненное, но недопустимое время считается отсутствием времени, а не полуночью.
- Имена профилей с `/` считаю допустимыми (это записано в `CONTEXT.md`); в имени файла заменяю разделители на `_`, а не транслитерирую кириллицу. К имени добавлен короткий хеш исходной строки, поэтому старые фото находятся по пути из БД, а не по совпадению имени файла.
- `updated_at` — достаточный cache-buster: он меняется при загрузке, замене и удалении фото; для этого повторная загрузка теперь явно его двигает.
- Публичный API: `baths_visited` в журнале стал nullable только для чтения старых записей; новые пишутся как `[]`. `free` теперь возвращает реальное значение PLC — это исправление бага, а не смена контракта.
- Рабочий стенд запущен в реальном режиме (PLC + сетевая книга), не в симуляции; перезапуск выполнен по инструкции `AGENTS.md` через Orca.

## Как откатить всё разом

Ничего не запушено. Откат ветки:

```bash
git checkout main
git branch -D night/2026-11-08
```

Снять всю ветку одним обратным коммитом, не удаляя её:

```bash
git revert --no-commit 14d41ac..night/2026-11-08
git commit -m "revert: night/2026-11-08"
```

Диапазон `14d41ac..night/2026-11-08` git разбирает сам в обратном порядке; проверено на временном worktree — exit 0, конфликтов нет, дерево совпадает с `main`. Перечислять хеши вручную в хронологическом порядке нельзя: `catalog_service.py` правят четыре коммита, и `git revert` в прямом порядке даст конфликты.

Точечно — по одному коммиту, от нового к старому:

```bash
git revert cc7c348 0deef96 51162d3 58ceb0b d89e4a6 04c2d60 6be68a7 cf388b7 a52b935 462ad3f 0b0641b 456f5b3 016bf28 3c3c4f7 5ba6118 968cfbe
```

После отката стенд нужно перезапустить: `npm run dev:kill; npm run dev`.
