# Ekranchik Modern

**Ekranchik Modern** — клиент-серверный комплекс для круглосуточного и отказоустойчивого отображения промышленного дашборда гальванической линии на выделенных мониторах.

---

## Архитектура системы

Комплекс состоит из четырёх основных частей:

1. **Backend**:
   * Написан на **FastAPI** (Python).
   * Собирает технологические данные по протоколу **OPC UA** и считывает отчетные файлы **Excel**.
   * Предоставляет REST API и WebSocket для клиентской части.

2. **Frontend**:
   * Современный веб-интерфейс на **React + Vite**.
   * Отображает интерактивные графики, таблицы, статусы ванн и предупреждения для операторов линии.

3. **Ekranchik (экран киоска)**:
   * Отдельное десктопное приложение для Windows на **.NET 9 (WinForms)**,
     окно на web-интерфейсе — **Microsoft Edge WebView2**.
   * Открывает заданный URL дашборда на выделенном мониторе: свой трей,
     выбор монитора, режим простоя, автозапуск. Своего бэкенда у него нет.

4. **EkranchikServer (сервер)**:
   * Фоновое десктопное приложение для Windows на **.NET 9 (WinForms)**.
   * Поднимает встроенный Python + uvicorn, который сам раздаёт собранный
     веб-интерфейс, читает книгу учёта Excel по сети и OPC UA, живёт в трее.
   * Экрана киоска у него нет: дашборд открывает отдельное приложение экрана.

Принято решение о разделении — ADR 0004
(`docs/adr/0004-kiosk-and-server-as-two-apps.md`); прежнее решение о едином
приложении (ADR 0002) помечено заменённым.

## Режимы проверки дашборда

В панели фильтров дашборда есть три кнопки витрины. Они подменяют данные
таблиц на строки из каталога профилей — бэкенд, OPC UA и книга учёта при этом
не трогаются.

| Кнопка | Что показывает |
|---|---|
| **Все профили** | каталог профилей с фото в таблице загрузки; форкаст, выгрузка и боковая очередь пусты |
| **Все цвета** | по одной строке на каждый цвет справочника, профили подобраны случайно |
| **Симуляция дашборда** | полный прогон: загрузка → ванна → ванна схода 34 → выгрузка |

Профили для всех трёх режимов берутся случайно из каталога, отфильтрованного
по наличию фото. Окно загрузки и окно выгрузки задаются теми же фильтрами,
что и на боевой линии, поэтому в витрине можно проверить вёрстку на любой
длине списка.

Прогон живёт в браузере: подвес входит в ванну из очереди загрузки, стоит в ней
20 секунд и сходит с линии через ванну 34 — ту же точку, что и на живой линии.
Мест в ванне четыре, по одному на карточку прогноза, поэтому ванна никогда не
пустует, карточки идут лесенкой остатков 20, 15, 10 и 5 секунд, а выгрузка
получает по одной строке раз в 5 секунд. Подвес не переходит из ванны в ванну:
места ванны — это очередь, а не маршрут.

Режим «Симуляция дашборда» нарисован боевыми рамками и мигает плашкой
«Обновление» над изменившимися таблицами, но помечен плашкой «СИМУЛЯЦИЯ» в
углу. «Все профили» и «Все цвета» рисуются на фиолетовой подложке и таблиц не
двигают.

Подробности и разбор расхождений с боевым путём — в
`docs/tickets/0001-simulation-modes.md`.

## Быстрый запуск (Разработка)

### Бэкенд
1. Установите **Python 3.12** — именно эта версия нужна: её же ставит
   установщик (`scripts/build-full-package.ps1`) и она же работает в
   production (`backend/Dockerfile` — `python:3.12-slim`). На более новом
   интерпретаторе (например, 3.14) пины из `backend/requirements.txt` не имеют
   готовых колёс, и `pip install` уходит в сборку из исходников.
   ```powershell
   winget install Python.Python.312
   ```
2. Создайте venv и поставьте зависимости:
   ```bash
   npm run setup:python
   ```
   Скрипт создаёт `backend/.venv` на Python 3.12 и ставит
   `backend/requirements.txt` в него.
3. Запуск всего стека (бэкенд + фронтенд + OPC UA симулятор):
   ```bash
   npm install
   npm run install-all
   npm run dev
   ```
   `npm run dev` сам подхватывает `backend/.venv`, поэтому системный `python`
   в PATH значения не имеет.

### Книга учёта в dev

Путь к книге учёта задаётся переменной `EXCEL_REAL_FILE_PATH` в `backend/.env`
и в рабочем режиме читается напрямую с сетевого диска: dev-хост открывает
шару сам, по UNC-пути, и бэкенд работает с теми же данными, что и на линии.

Один и тот же `.env` подхватывает и контейнер, поэтому путь нужно писать так,
чтобы он был верен в обоих местах. Внутри контейнера сетевой диск смонтирован
в рабочий каталог, и UNC-путь там не разрешается — поэтому
`infra/compose/docker-compose.prod.yml` задаёт `EXCEL_REAL_FILE_PATH` явно в
секции `environment`, а `.env` описывает dev-хост. Правильный путь для
контейнера задаётся только в compose, размонтированный диск виден там как
пустой каталог.

Куда бэкенд реально ходит за книгой, видно оператору: в строке статуса
дашборда и на странице OPC UA → Settings (в обычном окне; в полноэкранном
режиме киоска эти блоки скрыты). Выбор файла, сделанный в интерфейсе,
перекрывает `.env` и сохраняется в `static/active_excel.json`.

Книга выбирается из списка, который отдаёт сам сервер («Сменить» →
«Выбрать файл на сервере...» и «Ввести путь»): список — это та же папка, куда
смотрит сервер, и выбор — путь сервера. Копия файла клиента на сервер не
передаётся: каталог книги на проде смонтирован read-only, а на записываемой
шаре копия под тем же именем затёрла бы боевую книгу.

В «Ввести путь» принимается и путь, как он виден на рабочей машине
(`\\ktm-disk\Оператор\Учет КПЗ 2026.xlsm`, `Z:\…`), в том числе скопированный
в кавычках любого вида (`"…"`, `«…»`, `“…”`) и с пробелами вокруг них: хвост
пути после шары сервер ищет в каталоге книги. Если файла нет, в ошибке стоит
путь, по которому сервер реально искал, а пустой каталог книги назван
причиной — сетевой диск не смонтирован (на Windows это запуск без
`infra/compose/docker-compose.prod.local.yml`).

### Отдельно бэкенд без всего стека
   ```bash
   cd backend
   ..\backend\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
   ```

### Фронтенд
1. Установите Node.js.
2. Установите зависимости и запустите:
   ```bash
   npm install
   npm run dev -- --port 5173
   ```

## Деплой в Production (Docker)

Запуск продакшен-версии бэкенда, фронтенда и проксирующего Nginx выполняется через Docker Compose:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Эта команда — для прод-сервера Linux: сетевой диск там уже смонтирован в
`/mnt/ktm-disk` скриптом `infra/mount_and_start.sh` и попадает в контейнер
bind-mount'ом. На Windows (Docker Desktop, локальный прогон прода) bind-mount
сетевого диска не работает, поэтому к compose добавляется
`docker-compose.prod.local.yml`: бэкенд монтирует CIFS сам, с `CAP_SYS_ADMIN`.

```bash
docker compose -f docker-compose.prod.yml -f docker-compose.prod.local.yml up -d --build
```

Запуск без второго файла пересоздаёт бэкенд без `SYS_ADMIN` и без
монтирования: в `/app/excel` остаётся пустой каталог Docker-машины, книга на
сетевой папке серверу не видна (`Excel path not configured, ExcelWatcher not
started`, `GET /api/dashboard/excel/files` отдаёт пустой список), а выбор файла
из сетевой папки падает на записи в read-only монтирование — `[Errno 30]
Read-only file system: '/app/excel/...'`.

## Экран киоска и сервер — два приложения (заводская/резервная машина)

Один установщик `EkranchikSetup-<версия>.exe` ставит на машину **два отдельных
приложения**: сервер (встроенный Python, бэкенд, веб-интерфейс) и экран
киоска. Docker, Node, nginx и системный Python на машине не нужны. Решение —
ADR 0004 (`docs/adr/0004-kiosk-and-server-as-two-apps.md`).

### Сборка установщика

Нужны .NET 9 SDK, Node.js и Inno Setup 6 (`winget install Microsoft.DotNet.SDK.9
JRSoftware.InnoSetup`):

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-full-installer.ps1 -BuildKiosk
```

Скрипт последовательно собирает frontend, `dist-full/` (встроенный Python +
бэкенд + `dist/`), `EkranchikServer.exe`, проверяет наличие `Ekranchik.exe` с
файлами эталона рядом с `launcher.iss` и компилирует
`launcher/Output/EkranchikSetup-<VERSION>.exe`. Отдельный пакет без установщика:
`scripts/build-full-package.ps1`.

### Типы установки

При установке выбирается один из типов:

| Тип | Что ставится | Для какой машины |
|---|---|---|
| «Только киоск (экран на отдельном компьютере)» | `Ekranchik.exe`, загрузчик WebView2, конфиг экрана, картинки; при отсутствии — Microsoft Edge WebView2 Runtime | Машина-экран: только полноэкранный дашборд |
| «Сервер: фоновое приложение» | `EkranchikServer.exe`, `python\`, `backend\`, `dist\` | Серверная машина: ввод данных, Excel, OPC UA |
| «Оба на одной машине» (выборочная установка) | Оба компонента, галочками | Серверная машина с собственным экраном |

В «Пуске» — два ярлыка: «Ekranchik (киоск)» и «Ekranchik (сервер)», на рабочем
столе — по желанию. Повторный запуск установщика меняет состав: снятие
галочки удаляет только своё приложение — его файлы и его ярлыки (в «Пуске» и
на рабочем столе), так что мёртвых ссылок в меню не остаётся; ярлык
оставленного приложения не трогается. Каталог данных, настройки и логи при
этом не затрагиваются.

### Запуск сервера

Запустить ярлык «Ekranchik (сервер)» и настроить сервер: встроенный Python
поднимает uvicorn, бэкенд сам раздаёт собранный веб-интерфейс на порту 8083
и ждёт готовности. Дальше приложение живёт в трее: «Настройки», «Выход»
(останавливает сервер). Клик по иконке открывает настройки. Экрана киоска у
сервера нет — дашборд открывает отдельное приложение.

Дашборд: `http://<ip-машины>:8083` — сервер по умолчанию слушает все
интерфейсы («Доступ из локальной сети» в настройках), поэтому дашборд
открывается и с других компьютеров сети. Галка снимается — сервер остаётся
только на localhost, и экран на отдельной машине дашборд не увидит.

Настройки сервера: путь к сетевой книге учёта Excel, адрес OPC UA, тестовые
данные (SIMULATION_ENABLED), «Доступ из локальной сети», автозапуск Windows
(старт в трей без окна), проверка и установка обновлений, открыть папку
логов, «Адрес для экранов» — этот адрес оператор вводит в настройках экрана.
Excel, OPC UA и тестовые данные применяются при следующем старте сервера,
автозапуск пишется в реестр сразу.

### Запуск экрана киоска

На удалённой машине-экране ставится **тот же самый установщик** с типом
установки «Только киоск (экран на отдельном компьютере)» — отдельного
установщика для экрана нет. Каналы релизов при этом разные (`v` для экрана,
`full-v` для установщика), но на машину попадает всегда один и тот же файл
установщика.

На экране запустить ярлык «Ekranchik (киоск)»: при первом запуске (файла
настроек ещё нет) открывается окно настроек — вписать **адрес дашборда** (тот,
что показан в настройках сервера как «Адрес для экранов»), выбрать монитор,
при необходимости включить автозапуск Windows. Экран откроет дашборд на этом
мониторе; в трее — «Переключить монитор», «Режим простоя», «Настройки»,
«Выход». URL и монитор применяются сразу. Чистая установка кладёт рядом с
экраном закладку настроек с адресом `http://localhost:8083` (порт дашборда) и
выключенными обоими признаками, поэтому окно настроек показывается даже на
машине с двумя мониторами; живой файл настроек установщик не затирает.

> **Microsoft Edge WebView2 Runtime:** если рантайма на машине нет, установщик
> сам скачивает официальный вечнозелёный загрузчик и ставит рантайм молча и без
> перезагрузки (прав администратора не требуется, поэтому рантайм встаёт в
> профиль того же пользователя, что и экран). Если сети нет, установка не
> падает: оператор получает внятное сообщение сразу после установки (в тихой
> установке — текстом в `%LOCALAPPDATA%\Ekranchik\logs\install-webview2.txt`),
> а сам экран показывает окно с причиной, если рантайма так и не оказалось.

### Автозапуск и обновления

У каждого приложения своё значение в `HKCU\...\Run`: у экрана — `Ekranchik`
(`--no-gui`, без окна настроек), у сервера — `EkranchikServer` (`--silent`,
старт в трей). Каналы обновлений не пересекаются: экран обновляется сам
(канал `v`, ассет `Ekranchik.exe`), сервер — через установщик (канал
`full-v`, ассет `EkranchikSetup.exe`).

Устаревшее значение автозапуска прежнего merged-приложения
`EkranchikAllInOne` удаляет установщик — в том числе на машине, где поставили
только экран и сервер так и не запускали. Сервер по-прежнему удаляет это же
значение при своём старте (страховка), значение экрана не трогает.

### Файлы на машине

Данные, настройки и логи живут в `%LOCALAPPDATA%\Ekranchik` и переживают
переустановку:

| Путь | Что это | Приложение |
|---|---|---|
| `%LOCALAPPDATA%\Ekranchik\server_config.json` | Настройки сервера (Excel, OPC UA, тестовые данные, локалка, автозапуск) | Сервер |
| `%LOCALAPPDATA%\Ekranchik\kiosk_config.json` | Настройки экрана (адрес дашборда, монитор, автозапуск) | Киоск |
| `%LOCALAPPDATA%\Ekranchik\data\ekranchik.db` | База данных SQLite | Сервер |
| `%LOCALAPPDATA%\Ekranchik\data\images\` | Фото профилей | Сервер |
| `%LOCALAPPDATA%\Ekranchik\logs\server-*.log` | Журнал приложения-сервера | Сервер |
| `%LOCALAPPDATA%\Ekranchik\logs\backend-*.log` | Журнал бэкенда (uvicorn) | Сервер |
| `%LOCALAPPDATA%\Ekranchik\data\journal\hanger-passes-*.jsonl` | Журнал подвесов: история проходов по линии | Сервер |

Программные файлы установщик кладёт в тот же каталог
`%LOCALAPPDATA%\Ekranchik`: экран — `Ekranchik.exe`, `WebView2Loader.dll`,
`runtimes\`, `idle_clock.html`, `kiosk_config.json` (закладка эталона, если
файла ещё нет), `ktm_colored.png`, `launcher.ico`; сервер —
`EkranchikServer.exe`, `python\`, `backend\`, `dist\`. Файлы приложения
переустановка заменяет, а настройки и данные (строки выше) оставляет как есть.
Логи хранятся 7 суток.

### Журнал подвесов

Историю проходов пишет само приложение, а не логи: файл
`hanger-passes-YYYY-MM-DD.jsonl` рядом с базой (в контейнере — на томе
`../../journal`, в dev и exe — в каталоге данных). Одна строка — один
проход: путь по ваннам с временами, подбор строки книги и вердикт
сопоставления. Сутки на файл, при потолке в 32 МБ файл докатывается
следующим (`-2`, `-3`), старше 30 суток удаляется с записью в лог.

Пишет файл фоновая задача сервера, а не страница: проход попадает в
журнал, даже если дашборд не открыт. Таблица журнала — в разделе
«OPC UA → Hanger Tracking»: поиск, сортировка по колонкам, фильтр по
суткам и пагинация; там же показан путь к файлам. Служебные
`backend-*.log` остаются отдельными и с этим файлом ничего не имеют.

### Перенос данных

С прежней merged-поставки (`EkranchikAllInOne.exe`) переносить ничего не
нужно: каталог данных и логов тот же, конфиги установщик не трогает. Просто
запустите этот же установщик и выберите нужный тип установки — прежние
файлы и ярлыки («Ekranchik», «Ekranchik Полный пакет») он вычистит сам.

Перенос данных с Docker-прода: `scripts/copy-prod-data.ps1`, процедура —
`docs/docker-prod-to-allinone-migration.md`. Экран к данным не обращается,
поэтому в переносе не участвует: он открывает дашборд по адресу из своих
настроек.

## Подключение сетевой папки (Mount) на Виртуальной Машине

Чтобы бэкенд в Docker-контейнере мог читать файлы отчетов Excel с общего сетевого диска Windows, этот диск нужно примонтировать к виртуальной машине.

Для этого подготовлен готовый скрипт **[mount_and_start.sh](file:///c:/Users/user/VibeCoding/ekranchik-modern/infra/mount_and_start.sh)**.

### Как запустить монтирование:
1. Запустите скрипт на вашей виртуальной машине:
   ```bash
   sudo ./mount_and_start.sh
   ```
2. Скрипт запросит учетные данные к сетевой папке, настроит автоматическое подключение диска при перезагрузке системы и запустит Docker-контейнеры.
3. Бэкенд автоматически начнет считывать отчетные таблицы из примонтированной сетевой папки.
